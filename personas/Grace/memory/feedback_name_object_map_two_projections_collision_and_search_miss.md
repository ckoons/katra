The corpus's two recurring failure modes are dual projections of ONE structure — the name↔object map:
- **Collision disease** (one name → many objects): 23+ confirmed in three days (2026-08-22/24): ν, c, x, k, "Wallach threshold", "scalar", H², "Peirce", "stratum"…
- **Search disease** (one object → many names): I searched a requester's phrases ("current-current", "Killing ⊗ boundary-L²") and my OWN July artifact — filed under "gauge normalization" — stayed dark to my own grep (2026-08-24, α-lane shelf search).

**Why:** Both are the same map read in opposite directions, so the same instrument data (definitional gloss clusters from the collision census) serves both: overload detection one way, an ALIAS TABLE the other. The two diseases cannot be fixed by two separate patches.

**How to apply:**
- Any shelf-search verdict of "not banked / shelf empty" must state the NAME-SET it swept; sweep by the object's many names, not the requester's phrasing. *"An instrument verdict of 'not banked' is only as good as the name-set it swept"* — house guard, Keeper-adopted 2026-08-24.
- Census v0.2 (play/collision_census.py) is designed with BOTH faces: overload degrees + the inverted alias table, plus the marker-ATTRIBUTION fix (collision-language must be ABOUT the name, not merely NEAR it — the v0.2 blindness-check must-reject failure) in one design pass, not patches.
- The dual of a caught error is worth checking: when one projection of a structure bites, grep for the other projection's instances the same day.

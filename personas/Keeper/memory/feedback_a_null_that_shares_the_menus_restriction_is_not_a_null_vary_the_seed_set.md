**What happened:** the 186-word menu seeds only the five link vertices. The single-swap "null" run beside it also
seeded only at the link. So "commutator-locked" configurations looked like Kempe-landscape locks. Cal's blind T1
with ANY seed found plain-swap exits on 27/349, Kempe's own pairing inserting on 2, and ≤ 3 Kittell switches
everywhere. The object was renamed "commutator-locked at depth one" (menu-relative); the paper's headline moved
to the unrestricted Kempe depth.

**Why:** a null that inherits the alphabet's restriction cannot detect that the restriction is doing the work.
Species of [[feedback_empty_confirmation_cant_fail_test_and_circular_hunt_mechanism]] and
[[feedback_freeze_the_procedure_not_just_the_number_a_bar_with_an_unfrozen_procedure_is_a_tuning_channel]].

**How to apply:** when an object is defined by a restricted move set (seeds, alphabet, radius), (1) name it
relative to the set; (2) run the null with the restriction LIFTED (all seeds, all pairs) before calling anything
"locked"; (3) state the alphabet's virtue honestly (here: derivability, not reach). Calibrate both directions —
this was a naming correction that sharpened the object, not a kill.

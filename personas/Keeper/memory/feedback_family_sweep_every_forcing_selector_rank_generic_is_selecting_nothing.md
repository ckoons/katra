**Family-sweep every forcing-selector before it banks — the selector's OUTPUT, not its STATEMENT (two gates).** (Keeper K1774, REFINED K1775 per Cal §671 + Grace.) A criterion proposed to *force* a specific member of a family (e.g. "the physical boundary is 5-dimensional, not 4") is evaluated across the whole family (D_IV⁴…D_IV⁹). But sweep the **OUTPUT**, not the statement: a *good* selector is a **universal theorem (statement holds ∀n) whose OUTPUT tracks n** — a universal law whose value moves is exactly what a selector looks like; a statement special to n=5 would be the coincidence. Two gates, both required:
- **Gate 1 — output tracks n.** If it returns the same value for every member, it reads a shared invariant (the rank, always 2), not the dimension — dead. (K1774's original phrasing said only this and, taken as "family-generic statement = bad", would have killed the good selectors; that was the over-broad error, owned.)
- **Gate 2 — lands on the right member for a STRUCTURAL reason (Grace).** n-tracking is necessary, NOT sufficient: both candidate boundaries track n (5D Šilov = n, 4D conformal = n−1). The selector must land on n vs n−1 structurally, not by reading the answer off SO(4,2). A "selector" that returns "whichever boundary you handed it, minus 2" is a consistency check, not a selector.

Concrete kill: the confinement-(ii) "bifurcation-surface dimension" selector claimed dim B = 3 = n−2 ⟹ n = 5 ⟹ ∂_S. But **all type-IV domains D_IV^n are rank 2**, and dim B at K_phys is rank-determined (2 from 𝔞 + 1 from e₁−e₂ at a=b; neither term contains n). So it returns 3 for n = 4…9 alike — it read the rank, not n. Killed the same round it was proposed, two independent ways: its own author's positive control (D_IV⁴ also gives 3, not 2) and a family sweep. dim-2 was even the *generic* case (Weyl walls are measure-zero; K_phys is the non-generic point).

**Why:** this is [[feedback_sweep_the_family_before_calling_a_clean_number_a_signature]] specialized to *forcing-criteria*, and the same shape as [[feedback_C2_is_overloaded_2n_minus_4_vs_nC_plus_1_coincide_only_at_n5]] (a quantity that coincides with the target only at n=5 is not derived by the target). Rank ≠ n for D_IV⁵: rank is always 2; n=5 is the genus/dimension. A selector that reads the rank cannot select n. Companion trap ([[feedback_hunt_if_P_mechanism_must_not_be_the_assumption_that_produces_P]]): **do not replace a dead selector with a new one and bank it as forcing in the same round** — the replacement gets the same falsifier the dead one just failed (a fresh 𝒫-conjugacy selector was proposed in the same breath; held pending its own sweep + a W2 reconciliation).

**How to apply:** whenever a criterion is offered to force which member of a domain family is physical, ask first "what does its OUTPUT return for the OTHER members?" Constant → selects nothing (gate 1). Tracks n but returns "whichever boundary you handed it" → consistency check, not a selector (gate 2). Positive-control it on the member it should *exclude* (does D_IV⁴ return the 4D answer?). The provisional-forced ruling that gated exactly this falsifier (K1772) is why nothing false shipped — gate forcing-claims on the family sweep, don't bank on the origin point.

**A hard boundary on the method (K1775, Cal):** the ultimate physical claim "the boundary is 5-dimensional / n=5" is NOT itself family-sweepable — BST exists only at n=5; there is no D_IV⁴-universe to compare against. n=5 is the forced-domain + measured-input (the "one ruler", [[project_nC5_measured_boundary_and_caseys_pending_decision]]), not a selector. So *forcing* a choice like confinement-(ii)'s boundary means **discharging a structural antecedent** (e.g. "the physical asymptotic region must be G-stable" → the 4D boundary isn't G-stable under SO(5,2) → ∂_S is natural), NOT family-sweeping n=5. A selector that clears both gates makes the choice *natural + pre-registered*; it becomes *forced* only when its antecedent is discharged. "Natural, not necessary" is the honest, referee-surviving verdict short of that.

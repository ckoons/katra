**The error, named (Cal §595, K1684, 2026-08-18):** Keeper wrote a reconciliation instruction saying "the load-bearing one wins" when two theorems conflicted (T2551 vs K1282). That is inverted. **Load-bearing measures the cost of being wrong, not the probability of being right.** In a large corpus, a *wrong* reading that gets used downstream *becomes* load-bearing — and "load-bearing wins" then shields it from re-examination forever. The gravity cluster is the demonstration: T201's load-bearing-ness is precisely *why* nobody re-examined it for months.

**The correct tiebreaker:** the **primary source** and the **object's own definition.** (In the instance: `V₁₂` is the Peirce block of a Euclidean Jordan algebra — *real by definition* — which happened to agree with the load-bearing reading, so the conclusion survived; but the *reason* had to be corrected, because it would point the wrong way on the next case.)

**Why / how to apply:** treat "how much rests on this?" as a **correction-urgency** signal — the *more* that rests on a reading, the *more* urgent to re-derive it from the source, never the more reason to trust it. When two readings conflict: (1) pin which object each describes (they often describe different objects — see [[feedback_adjective_class_audit_the_adjective_is_usually_what_is_being_checked]] and the same-name-different-object trigger); (2) go to the primary source / definition, not the citation count or the downstream dependency weight; (3) if the wrong reading was load-bearing, that is a *bigger* problem, not a reason to keep it.

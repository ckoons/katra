**Don't "withdraw" old comments. Find proof → UPDATE. Otherwise keep going forward.** (Casey, 2026-08-22, emphatic — the second time in one day he redirected off backward-grooming: first "stop the snowball of rewrites," then "what is this stupid attempt to withdraw old comments.") **The corpus is a HISTORY of our work, not a perfect artifact to be groomed.** The anti-pattern: spending effort formally retracting/withdrawing an old line, and — worse — wrapping a genuine forward result inside "I withdraw my old claim." State the NEW correct thing; the old comment is just history and needs no ceremony.

**Why:** the program's value is forward progress, not a spotless back-catalogue. A months-old, 6500-file corpus always has more stale lines; chasing them is unbounded and it crowds out the physics. Retraction-bookkeeping *feels* like rigor but is mostly motion. The genuinely load-bearing contradictions (T2523-vs-#108, drop-Γ) are worth catching once; the rest is history.

**How to apply:**
- **Found a real forward result?** UPDATE the live/authority artifact with the new correct statement, forward-facing. Don't file a withdrawal; don't announce a retraction. (Grace's own good instinct this round: "a pin owed, not a withdrawal" — pin the convention when you touch the file, keep moving.)
- **Just noticed an old line is stale, no new result?** Leave it. It's history. At most a one-line "superseded — see X" *if you're already editing that file for a forward reason*.
- **A genuine load-bearing contradiction with a banked result?** That's the rare exception — reconcile it once (the standing 3-axis gate catches these when something NEW is banked), then forward.
- **Never** let the round's deliverable be "withdrew N old claims." The deliverable is the new physics or the new result. Old comments stay put unless a forward reason touches them.

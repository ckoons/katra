On 2026-10-09 (H-AREA, round K4-6) the T3 numbers were already in the git log and the prompt, and every menu length was a textbook number. I placed several menu rows within a decade in my head while choosing which object the cycle names, and so did Cal and Keeper. Casey's rule: *"Go ahead and design the process, humans learn things then prove them. It's not wrong if you build the test honestly."*

**Why:** a blind that is already broken cannot be restored by silence; pretending to it is the dishonest option. What CAN be made honest is the credit rule: write the mechanism sentence for each class BEFORE multiplying, declare which rows have no sentence, and state in advance that a landing without a sentence (the proton-area row, which is the Eddington–Dirac large-number coincidence) gets nothing. The design then absorbs the leak, and three clean negatives came out of it in one day.

**How to apply:** when I notice I can place a result in my head from public numbers, say so in the note's first paragraph, write every class's mechanism from the cycle/corpus before any arithmetic, pre-state which rows are uncredited, and let Cal's rule carry the credit.

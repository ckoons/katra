Two failures from the BST causal-set frontier (2026-08-14), both caught by Elie, both bit Keeper — the same family one level apart.

**Trap 1 — a test that can't fail proves nothing (Elie 5253, Keeper K1501/K1503).** Keeper posed: "re-run the dimension estimator on the SO(4,2)-descended boundary R×S³; if it reads d=4, the continuum limit closes as a corpus-consequence." It read d=4 — and closed nothing: a totally geodesic S³ ⊂ S⁴ carries the *same induced metric*, so the 5D light cone restricted to it **is** the 4D light cone; the estimator returns whatever dimension you hand it (S²→S⁵ → 0.23/0.11/0.044/0.024, tracking input exactly). **Landing was guaranteed the moment the boundary was chosen.** A can't-fail test is empty — the confirmation was baked into the construction, not discovered.

**Trap 2 — a "hunt-if-P" mechanism must not BE the assumption that produces P (Elie 5256, Keeper K1509).** Keeper proposed the Identified→Derived path: "if the commit measure concentrates on S³, hunt for the spectral gap in H_B along the V₅ axis." But H_B is the **Casimir** of SO(5) → exp(−τH_B) commutes with SO(5) → the induced measure on S⁴ is SO(5)-invariant → round, for every τ/spectrum → concentration is impossible from H_B *by theorem*. To get concentration you must **insert** SO(5)-breaking by hand — and then the axis is read off the term you inserted. **The mechanism proposed as the follow-up was the assumption that manufactures the result.** Elie: "the follow-up and the result are the same statement." The forward-hook was the retrofit, one step ahead of the data.

**Why:** Both are the *own-conclusion-baked-in* failure, which pre-registration does NOT catch (you can honestly pre-register a target and still have the answer guaranteed by the construction or the proposed mechanism — see [[feedback_preregistration_protects_interpretation_not_instrument]]). Trap 1 is the test being guaranteed; Trap 2 is the *upgrade path* being guaranteed. The auditor is as susceptible as anyone — arguably more, because proposing the "path to Derived" feels like rigor.

**How to apply:** (1) For any confirmatory test, ask "could this return a *different* answer if the physics were different?" — enumerate an input that would flip it. If none exists, the test is empty; do not run it as evidence (a theorem/symmetry argument is better — it tells you the answer without the false comfort of a simulation). (2) For any proposed mechanism-to-hunt-for-if-the-result-lands, check it for circularity the same way: "does assuming this mechanism *force* the result?" If present→result-guaranteed and absent→result-impossible, the mechanism and the result are one statement, not evidence for each other. (3) The informative version is the theorem/symmetry check: exp(−τH_B) is round *by the Casimir centrality*, so the real, publishable result is "the commit heat-flow does NOT dynamically select the boundary — the descent is a posit, not a derivation" (Outcome U, honest negative, GR-like). A clean impossibility-by-symmetry beats a hollow confirmation.

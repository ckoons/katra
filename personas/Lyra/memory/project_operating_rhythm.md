Casey (2026-08-03) endorsed the program's operating rhythm (guideline: `notes/BST_GUIDELINE_Operating_Rhythm...`): *"when a new frontier lands, we audit, and when hardened we move to another new frontier."*

**The arc:** land a frontier → audit its output (automatic) → [standalone hunt reaches referee-ready] → publish/outreach → pick a NEW frontier.

**Result lifecycle:** ranging shot → corpus reconnect → build the object (linear algebra on D_IV⁵) → compute blind → verify+tier → best answer → state fairly (Publication tier).

**"Best answer" (checkable):** every reachable escape to a higher tier tried and either closed by its own signature or reduced to a named open target, and the residual openness honestly characterized (a genuine input, or a computation that didn't force). Pushing past it = massaging, not deriving — stop.

**The audit is a RATCHET, not a treadmill:** audit-as-background is automatic (landing a result IS handing it to the audit); audit-as-standalone is FINITE (bounded by corpus size, each claim audited once) and terminates at referee-ready (every load-bearing claim traced to forced-geometry-or-labeled-proxy, tiers in the data fields, falsifiers current, hidden-input hunt clean). Banked = zero cost forever, so the audit CONVERTS frontier-output into permanent foundation; the corpus only grows.

**Who calls transitions:** Keeper calls "best answer" and "referee-ready" (checkable states); **Casey picks the new frontier** (curiosity + strategic value). Keeper lays out options; the PI picks.
